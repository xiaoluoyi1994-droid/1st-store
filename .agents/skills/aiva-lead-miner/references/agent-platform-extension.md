# Agent和平台扩展接口

第一期入口是scripts/core.mjs导出的 `runJob(configFile,{targets})`，返回任务摘要与输出位置。命令行stdout同样为JSON，退出码区分成功和失败，便于Agent/任务队列复用。parsePosts和parseComments是独立纯函数，可对平台字段变化单独替换和测试。HTTP provider可接入经过验证的数据源，不改变输出schema_version:1。

升级顺序：
1. Agent调用runJob，读取report，针对失败重试或提示人工登录，读取JSONL做进一步意向判断。
2. 平台增加账号圈选页面、租户配置、任务队列、运行历史、登录状态管理和结果下载。按不同租户隔离会话和输出目录，禁止合用客户数据。
3. 将state.json替换成数据库和唯一约束，增加运行锁租约、更新/删除策略、限流和失败重试。保持record_key、job_id、平台ID类型及时间语义。
4. 封装MCP/API只暴露圈选管理、运行任务、查询状态和下载结果。新媒体候选与自主留资后的销售线索分别存储；承接回传只用于规则改进，不默认自动联系用户。

当前尚未交付Web平台、远程任务服务器、LLM评分或第三方官方数据接口，不能因保留扩展入口声称这些能力已经上线。
