## 具体修订

1. HTTP来源声明complete，但程序本地上限截断返回记录时，报告coverage改为limited。来源声明不等于独立核验。
2. 累计导出按任务ID、平台和account_id联合过滤。复用任务ID并改绑账号后，不再展示原账号记录；旧状态保留。
3. 平台缺少评论ID时，回退去重键使用规范时间；同一时间的秒与毫秒表示不再产生不同键，原始值仍保留。
4. 调度测试使用当前宿主解析后的路径，移除POSIX专属断言；未改动调度实现。

browser.mjs和schedule.mjs与原包内容保持一致。首期范围、四个核心输出字段、圈选、增量、导出及定期命令均保留。

## 后续最小业务验收

对每个平台先选一个真实账号和一段明确时间范围，保留实际report及可回查的作品／评论证据。将原始评论冻结成独立样本，由业务复核者在不看Skill判断的情况下标注，再比较误判、漏判与待核验项。精确率=人工确认有效的候选／所有已复核候选；召回率只能在取得完整标注样本时计算。样本数与分母必须同时报告。

定期能力需要在同一运行机器完成一次真实成功采集后，安装计划并查看下一次实际运行及输出时间记录。GPT／Codex需要分别以对应版本执行一次任务。上述验收均不能由代码上传替代。
